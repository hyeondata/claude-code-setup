# Claude Code 개발용 MCP·플러그인 추천

조사 기준일: **2026-11-01**. 공식 문서와 개발자 저장소를 확인해 정리했으며, 실제 설치·설정 변경·성능 비교 실험은 하지 않았다.
이 문서는 지금까지 검토한 개발 도구를 빠짐없이 정리한 선택 안내다. 전부 설치하라는 뜻은 아니다.
추천 우선순위는 작업에 추가하는 기능, 기존 기능과의 중복, 운영 부담을 고려한 판단이다.
설치 명령은 별도 설치 안내에서 다루며, 여기서는 선택 기준과 환경 조건에 집중한다.

추가 조사: [10 개발 도구 추가 조사](10_개발도구_추가조사.md)에서 구조 검색, 코드 묶음, 보안 검사, 브라우저 CLI, Flutter 공식 도구 등 10개 후보를 비교합니다. [08 내장 기능 심화](08_내장기능_심화.md)에는 새 플러그인보다 먼저 볼 기능을 정리했습니다.

## 먼저 고를 조합

| 사용 상황 | 우선 검토할 구성 | 필요할 때 추가 |
|---|---|---|
| 일반 개발 | 언어 LSP, 내장 `/code-review`, `CLAUDE.md`·auto memory | Context7, GitHub MCP |
| 큰 저장소 탐색·수정 | 언어 LSP를 먼저 사용 | Serena의 심볼 편집·기억 기능 |
| 기존 제품의 기능 추가 | 기본 구성 + 개발 절차 도구 하나 | Superpowers 또는 feature-dev |
| 여러 세션에 걸친 프로젝트 | 기본 구성 + 진행 상태 기록 도구 하나 | GSD Core 또는 planning-with-files |
| 웹 UI 개발 | frontend-design + 브라우저 검증 도구 | Playwright, Chrome DevTools, Figma |
| 반복 업무 자동화 | skill-creator, hookify | 팀에 배포할 때 plugin-dev |
| 서비스 운영 | 실제 사용하는 서비스의 MCP만 | Linear, Sentry, Supabase |

**우선**은 시작점으로 검토할 후보, **선택**은 특정 필요가 생길 때 추가할 후보, **고급**은 설정·사용량·절차 부담을 이해하고 도입할 후보다.
MCP는 외부 도구 연결 방식이고, 플러그인은 스킬·훅·에이전트·MCP 등을 묶는 배포 단위다. 같은 기능이 MCP와 플러그인 두 형태로 제공될 수 있다. [확장 기능 공식 설명](https://code.claude.com/docs/en/features-overview)

## 1. 기본 코딩·문서·저장소 연결

### 언어별 LSP 플러그인 — 우선

- **종류·주체:** 코드 인텔리전스 플러그인. TypeScript, Python 등 주요 언어용 플러그인은 Anthropic이 제공한다.
- **용도:** 편집 후 타입 오류·누락된 import를 확인하고, 심볼의 정의와 참조를 찾는다.
- **추천 상황:** 타입이 있는 언어, 관련 코드를 찾느라 파일을 많이 읽는 저장소.
- **환경:** 플러그인과 실제 언어 서버 실행 파일을 별도로 준비해야 한다. 터미널 세션을 기준으로 하며, cloud session에서는 플러그인 언어 서버가 시작되지 않는다.
- **겹침·비용:** Serena와 탐색·진단 기능이 일부 겹친다. 먼저 언어 LSP만으로 충분한지 확인하고, 검색 결과를 읽는 모델 사용량과 로컬 서버 자원을 고려한다. [공식 문서](https://code.claude.com/docs/en/plugins/code-intelligence)

### Context7 — 우선 검토

- **종류·주체:** Upstash의 문서 검색 서비스와 MCP·스킬 연동.
- **용도:** 라이브러리별·버전별 문서와 코드 예제를 개발 대화에 제공한다.
- **추천 상황:** 빠르게 바뀌는 프레임워크·SDK 사용법을 자주 확인할 때.
- **환경·비용:** 문서 검색 서비스에 접속하는 연결이며, 서비스의 인증 방식·요청 한도·요금제는 도입 시 확인한다. 로컬 실행형 MCP라고 문서 검색까지 오프라인인 것은 아니다.
- **겹침:** 공식 문서를 직접 여는 검색과 일부 겹친다. 모든 질문에 강제로 호출하기보다 API 사용법·버전 차이가 중요한 작업에 사용한다. [공식 저장소](https://github.com/upstash/context7)

### GitHub MCP — GitHub 업무가 많으면 선택

- **종류·주체:** GitHub 공식 MCP 서버. 원격 연결과 로컬 실행 경로를 제공한다.
- **용도:** 저장소, 이슈, PR, Actions 등 GitHub 작업을 대화에서 조회·처리한다.
- **추천 상황:** 코드 편집과 이슈·PR·CI 확인을 자주 오갈 때.
- **환경·비용:** GitHub 계정의 권한과 인증이 필요하며, GitHub API·서비스 조건과 Claude 사용량이 적용된다. 필요한 toolset만 활성화하거나 읽기 전용으로 사용할 수 있다.
- **겹침:** 로컬 `git`이나 이미 잘 쓰는 `gh` CLI로 충분한 작업도 있다. 로컬 파일 편집만 한다면 우선순위가 낮다. [공식 저장소](https://github.com/github/github-mcp-server)

### Serena — 큰 저장소·심볼 편집에 선택

- **종류·주체:** oraios의 코드 탐색·편집 MCP 도구.
- **용도:** 심볼과 관계를 중심으로 코드를 검색·수정하고, 장기 작업을 위한 기억을 관리한다.
- **추천 상황:** 여러 파일에 걸친 구조를 파악하거나 심볼 단위 수정이 반복될 때.
- **환경·비용:** 언어 서버 또는 지원 IDE 백엔드 등 실행 구성을 맞춰야 한다. 오픈소스 도구와 유료 Serena JetBrains 플러그인은 별도 선택지다.
- **겹침:** 기본 LSP와 탐색·진단이 겹치며, Serena 기억은 다른 기억 시스템과 역할을 정해야 한다. 속도·토큰 절감률은 이 문서에서 검증하지 않았다. [공식 저장소](https://github.com/oraios/serena)

## 2. 리뷰·Claude Code 설정 관리

### 내장 `/code-review` — 우선

- **종류·주체:** 최신 Claude Code에 포함된 bundled skill. 별도 플러그인 설치가 전제되지 않는다.
- **용도:** 현재 브랜치, PR, 경로, 커밋 범위의 변경을 검토한다. 수정·댓글 게시 옵션도 제공한다.
- **추천 상황:** 변경을 마친 뒤 버그와 개선점을 확인하는 기본 검토 단계.
- **비용:** 리뷰는 모델 작업이므로 세션의 구독 사용량 또는 API 과금에 포함된다. 백그라운드 실행이 무료라는 뜻은 아니다.
- **겹침:** `code-review` 플러그인과 일반 리뷰 목적이 겹친다. 우선 내장 기능을 사용하고, 분야별 검토가 부족하면 PR Review Toolkit을 추가한다. [공식 문서](https://code.claude.com/docs/en/code-review-local)

### code-review 플러그인 — 기존 흐름이 필요할 때만 선택

- **종류·주체:** Anthropic 플러그인. 여러 에이전트의 PR 검토와 신뢰 점수 기반 필터링을 묶는다.
- **용도:** 프로젝트 규칙, 변경 버그, 이력 맥락 등을 일정한 PR 검토 흐름으로 점검한다.
- **환경:** README는 GitHub 저장소와 인증된 `gh` CLI를 요구한다.
- **겹침·비용:** 내장 `/code-review`와 이름·목적이 겹치므로 신규 사용자의 필수 설치 목록에서 제외한다. 다중 에이전트 실행은 사용량을 추가한다.
- **문서 해석:** 개별 README의 오래된 설치 설명보다 최신 공통 플러그인 문서와 현재 catalog를 우선한다. [플러그인 저장소](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/code-review)

### PR Review Toolkit — 분야별 검토에 선택

- **종류·주체:** Anthropic의 `pr-review-toolkit` 플러그인.
- **용도:** 테스트, 오류 처리, 타입 설계, 주석, 코드 품질, 단순화를 분야별 에이전트로 검토한다.
- **추천 상황:** “테스트가 빠진 경계 조건”, “무시되는 예외”처럼 검토 초점이 구체적일 때.
- **비용:** 필요한 에이전트만 요청하면 검토 범위를 통제하기 쉽다. 매번 모든 에이전트를 실행하면 호출량이 커진다.
- **겹침:** 내장 리뷰·Superpowers 리뷰·feature-dev 검토와 일부 중복된다. 동일 변경을 여러 도구로 반복 검토할 이유가 있을 때만 병행한다. [공식 저장소](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/pr-review-toolkit)

### claude-code-setup — 초기 구성에 선택

- **종류·주체:** Anthropic 플러그인.
- **용도:** 실제 저장소를 읽고 MCP, 스킬, 훅, 서브에이전트, 명령 후보를 추천한다.
- **추천 상황:** 범용 추천 목록을 내 프로젝트에 맞게 좁히고 싶을 때.
- **환경·비용:** 읽기 전용 분석 도구다. 추천이 자동 설치·설정 변경을 의미하지 않으며, 코드베이스 분석에 모델 사용량이 든다.
- **겹침:** 현재 안내서보다 프로젝트별 맥락을 더 구체적으로 반영하는 보완 도구다. [공식 저장소](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/claude-code-setup)

### claude-md-management — 프로젝트 규칙 관리에 우선 검토

- **종류·주체:** Anthropic 플러그인.
- **용도:** `CLAUDE.md`의 내용과 현재 코드를 비교하고, 세션에서 배운 내용을 프로젝트 규칙에 반영한다.
- **추천 상황:** 같은 설명을 반복하거나, 프로젝트 지침이 오래되어 실제 코드와 어긋날 때.
- **환경·비용:** Markdown 파일을 점검·수정하는 흐름이며 모델 사용량이 발생한다. 변경 내용은 일반 파일처럼 검토·버전 관리할 수 있다.
- **겹침:** auto memory를 대체하는 전체 대화 저장소가 아니다. 팀 규칙은 `CLAUDE.md`, 개인 선호·발견은 기억 기능처럼 역할을 나누면 관리하기 쉽다. [공식 저장소](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/claude-md-management)

## 3. 개발 절차·장기 작업 관리

### Superpowers — 체계적인 개발 절차를 원하면 선택

- **종류·주체:** obra / Prime Radiant의 커뮤니티 플러그인. 공식 marketplace 등재와 Anthropic 자체 개발은 다르다.
- **용도:** 요구 파악, 설계, 계획, TDD, 서브에이전트 작업, 리뷰, 검증의 절차를 적용한다.
- **추천 상황:** 구현을 시작하기 전에 계획과 검증 기준을 정하고 싶은 개발 작업.
- **비용·환경:** 스킬이 자동 발동하는 강한 워크플로다. 질문·계획·테스트·검토가 추가되어 간단한 수정에는 절차가 무거울 수 있다.
- **겹침:** feature-dev, GSD, ECC와 주도하는 개발 방식이 겹친다. 처음에는 주 워크플로 하나를 정한다. [공식 저장소](https://github.com/obra/superpowers)

### feature-dev — 기존 저장소에 기능을 추가할 때 선택

- **종류·주체:** Anthropic 플러그인.
- **용도:** 저장소 탐색, 요구 확인, 설계 비교, 구현, 검토를 7단계로 진행한다.
- **추천 상황:** 기존 구조와의 통합을 고민해야 하는 중간 이상 규모의 기능 개발.
- **비용·환경:** 탐색·설계·리뷰에 복수 에이전트를 사용하고, 사용자 답변·선택을 기다리는 단계가 있다.
- **겹침:** Superpowers와 대체 선택에 가깝다. 작은 버그 수정마다 전체 절차를 실행하기보다 필요한 기능 개발에서 호출한다. [공식 명령 소스](https://github.com/anthropics/claude-plugins-official/blob/main/plugins/feature-dev/commands/feature-dev.md)

### GSD Core — 여러 세션의 프로젝트 진행 관리에 고급

- **종류·주체:** OpenGSD의 스킬·명령·에이전트·훅 기반 개발 프레임워크. 범용 MCP 기억 서버가 아니다.
- **용도:** 논의·계획·실행·검증·배포 단계를 관리하고, `.planning/`에 계획·결정·진행 상태를 남긴다.
- **추천 상황:** 여러 세션에 걸쳐 단계와 마일스톤을 이어가는 프로젝트.
- **환경·비용:** runtime 설치형과 네이티브 플러그인 경로의 요구 사항이 다르다. 조사·계획·실행·검증 에이전트와 모델 프로필에 따라 사용량이 달라진다.
- **겹침·이름 변경:** Superpowers와는 주 워크플로를 하나 선택하는 편이 명확하다. 과거 Get Shit Done 저장소는 GSD Core로 이동했으므로 옛 설치 명령을 그대로 사용하지 않는다. [현행 저장소](https://github.com/open-gsd/gsd-core), [설치 구조](https://github.com/open-gsd/gsd-core/blob/main/docs/how-to/install-on-your-runtime.md)

### planning-with-files — 가벼운 작업 상태 기록에 선택

- **종류·주체:** OthmanAdi의 파일 기반 계획 스킬·플러그인.
- **용도:** `task_plan.md`, `findings.md`, `progress.md`에 계획·발견·진행을 기록한다.
- **추천 상황:** 복잡한 작업을 중단했다 다시 이어가되 큰 개발 프레임워크까지 필요하지 않을 때.
- **환경·비용:** 작업 디렉터리의 파일이 핵심 저장소다. 기록을 읽고 갱신하는 모델 사용량이 들며, 파일이 쌓이면 작업별 정리가 필요하다.
- **겹침:** GSD의 진행 기록과 겹친다. 범용 장기 지식 검색 시스템으로 분류하지 않으며, 완료 후 자동 archive가 기본 제공된다고 가정하지 않는다. [공식 저장소](https://github.com/OthmanAdi/planning-with-files)

### ECC — 넓은 자동화 구성을 직접 고를 사용자에게 고급

- **종류·주체:** affaan-m의 ECC, 이전 Everything Claude Code로 알려진 커뮤니티 도구 묶음.
- **용도:** 스킬, 에이전트, 훅, 기억·자동화 구성 등 폭넓은 개발 기능을 제공한다.
- **추천 상황:** 여러 구성 요소를 이해하고 필요한 부분을 직접 골라 운영할 때.
- **환경·비용:** 오픈소스 프로젝트와 별도 hosted ECC Pro/GitHub App을 구분한다. 선택한 훅·에이전트가 실행하는 작업에 따라 사용량이 달라진다.
- **겹침:** Superpowers·GSD·별도 기억 도구와 중복 범위가 넓다. 안내형 설치·플러그인 설치·전체 수동 설치를 무심코 겹치지 않는다. [현행 공식 저장소](https://github.com/affaan-m/ECC)

### Ralph Loop — 완료 기준이 명확한 반복 작업에 고급

추가 비교: 현재 내장 `/goal`도 완료 조건까지 여러 턴을 진행하므로 먼저 검토할 가치가 있습니다. 설치형 반복 훅과 동일한 구현은 아니며, 모델의 완료 판단과 실행 증거를 함께 봐야 합니다. [공식 Goal 문서](https://code.claude.com/docs/en/goal)

- **종류·주체:** Anthropic의 `ralph-loop` 플러그인. 과거 이름은 `ralph-wiggum`이다.
- **용도:** Stop 훅이 같은 프롬프트를 다시 주입하며, 파일에 남은 결과를 바탕으로 작업을 반복한다.
- **추천 상황:** 실패하는 테스트를 통과시키는 등 기계적으로 확인 가능한 완료 기준이 있을 때.
- **비용·환경:** 반복마다 사용량이 쌓인다. 기본 최대 반복 횟수는 무제한이므로 도입할 때 반복 한도와 중단 조건을 명시한다.
- **겹침:** Superpowers의 개발 방법론이나 GSD의 프로젝트 상태 관리와 목적이 다르다. 내장 `/loop`의 일정·반복 실행과도 구별한다. [공식 README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/ralph-loop), [내장 명령](https://code.claude.com/docs/en/commands)

### security-guidance — 자동 보안 검토 사용량을 감수하면 고급

## 5. 웹 UI 제작·브라우저 검증

### frontend-design — 웹 UI 작업이면 선택

### Playwright MCP — 브라우저 상호작용·흐름 검증에 선택

- **종류·주체:** Microsoft의 브라우저 자동화 MCP 서버.
- **용도:** 구조화된 접근성 정보로 페이지를 읽고 클릭·입력 등 사용자 흐름을 수행한다.
- **추천 상황:** 폼, 탐색, 로그인 이후 화면 등 여러 단계의 웹 동작을 확인할 때.
- **환경·비용:** 로컬 런타임과 브라우저 구성이 필요하고, 페이지 정보·도구 응답이 컨텍스트를 사용한다. 실행되는 사이트의 데이터도 도구 결과에 포함될 수 있다.
- **겹침:** Chrome DevTools와 조작 기능이 겹친다. 공식 저장소도 코딩 에이전트용 CLI+Skills 대안을 안내하므로 MCP가 유일한 경로는 아니다. [공식 저장소](https://github.com/microsoft/playwright-mcp)

### Chrome DevTools MCP — 성능·네트워크 디버깅에 선택

- **종류·주체:** Chrome DevTools 팀의 MCP·CLI 도구.
- **용도:** Chrome 성능 trace, 네트워크 요청, 콘솔 오류, 화면과 동작을 조사한다.
- **추천 상황:** “화면은 뜨지만 느림”, “API 요청이 실패함”처럼 원인 분석이 필요할 때.
- **환경·데이터:** 공식 지원 브라우저는 Chrome과 Chrome for Testing이다. 연결 브라우저 내용이 MCP 클라이언트에 노출되며, 성능 기능은 CrUX API에 trace URL을 보낼 수 있다.
- **겹침:** 일반 흐름 검증은 Playwright, DevTools 중심 진단은 이 도구를 우선 검토한다. 처음부터 둘 다 상시 켤 필요는 없다. [공식 저장소](https://github.com/ChromeDevTools/chrome-devtools-mcp)

### Figma MCP — Figma를 디자인 원본으로 쓰면 선택

- **종류·주체:** Figma 공식 MCP 서버.
- **용도:** 파일의 디자인 맥락을 코드 구현에 연결하고, 지원되는 경로에서는 Figma 캔버스 작성도 수행한다.
- **추천 상황:** 실제 Figma 프레임·컴포넌트·변수를 기준으로 화면을 구현할 때.
- **환경·비용:** 원격·데스크톱 연결 방식과 계정·seat·요청 한도 조건이 다르다. 캔버스 쓰기 등 기능별 접근·요금 조건은 도입 시 공식 문서를 확인한다.
- **겹침:** 브라우저에서 이미 구현된 화면을 검증하는 도구와 역할이 다르다. Figma를 사용하지 않는 프로젝트에는 필수가 아니다. [공식 문서](https://developers.figma.com/docs/figma-mcp-server/)

### Sentry MCP — 운영 오류를 개발에 연결할 때 선택

### Supabase MCP — Supabase 백엔드를 쓰면 선택

- **종류·주체:** Supabase 공식 MCP 연결.

- **범위·겹침:** 프로젝트 제한, 읽기 전용, feature group 제한을 제공한다. 일반 CLI·마이그레이션 흐름으로 충분한 작업과 구별하고, 개발·운영 어느 프로젝트를 대상으로 하는지 명확히 한다. [공식 문서](https://supabase.com/docs/guides/ai-tools/mcp)

## 9. 설치 전 확인할 비용·환경

- **소프트웨어 배포와 모델 사용량을 분리한다.** 오픈소스 플러그인도 실행하는 리뷰·계획·평가에는 Claude 사용량이 든다.
- **서비스 비용을 별도로 본다.** Figma·Supabase 등 계정·seat·인프라 비용은 Claude 구독에 포함된다고 가정하지 않는다.
- **로컬 실행과 데이터 흐름을 구별한다.** 로컬 MCP가 검색 API를 호출할 수 있고, 도구 결과는 사용 중인 모델의 입력이 될 수 있다.
- **사용하는 표면을 확인한다.** 터미널, IDE, 데스크톱 로컬 세션, cloud session에서 플러그인·서버의 지원 범위가 같다고 가정하지 않는다.
- **설치 형태를 하나로 정한다.** 동일 서버를 플러그인과 직접 MCP 설정으로 중복 등록하거나 동일 워크플로를 수동·플러그인 양쪽에 복사하지 않는다.
- **공식 marketplace와 개발 주체를 구별한다.** 공식 목록에도 파트너·커뮤니티 도구가 포함된다. [공식 marketplace 설명](https://code.claude.com/docs/en/plugins/anthropic-marketplaces)
- **새 프로젝트에서는 작은 구성부터 시작한다.** 현재 프로젝트의 구체적인 불편이 생겼을 때 위 목록에서 해당 기능을 추가한다. [확장 기능 선택 가이드](https://code.claude.com/docs/en/features-overview)

공통 설치·범위·업데이트 동작은 [현재 플러그인 문서](https://code.claude.com/docs/en/discover-plugins)를, 설치 가능한 이름은 [공식 catalog](https://github.com/anthropics/claude-plugins-official/blob/main/.claude-plugin/marketplace.json)를 확인한다.
