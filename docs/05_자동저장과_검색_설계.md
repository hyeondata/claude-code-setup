# 자동 저장·검색·사용을 위한 설정 설계

기준일: 2026-11-01

이 문서는 **권장 설계**입니다. 실제 훅, 스크립트, 모델 호출, Obsidian 저장 작업을 설치하거나 실행하지 않았습니다. 기존 제품의 기본 동작과 추가 구현해야 할 부분을 구분합니다.

후속 요청으로 이 설계의 검색·선별 저장 기준을 전역 `CLAUDE.md`의 영어 지침으로 작성했습니다. 지침을 통한 자동 호출에는 새 훅 개발이 반드시 필요한 것은 아닙니다. 실제 적용 범위와 남은 연결 조건은 [CLAUDE.md 적용 안내](07_CLAUDE_md_적용안내.md)를 참고하세요.

## 기본 기능만으로 자동 처리되는 범위

| 구성 | 자동 기록·저장 | 자동 읽기·검색 | 추가 연결이 필요한 부분 |
|---|---|---|---|
| 내장 Auto memory | Claude가 유용하다고 판단한 내용을 선택해 기록 | 세션 시작에 인덱스를 로드, 상세 파일은 필요시 읽음 | 저장할 모든 내용을 강제로 보장하는 기능은 아님 |
| `CLAUDE.md` | 직접 편집하거나 Claude에게 갱신 요청 | 해당 범위의 세션에 자동 로드 | 대화에서 규칙을 자동 추출·반영하려면 별도 절차 필요 |
| episodic-memory | 현재 훅 기준 시작·재개·clear 시 기존 대화 sync·보관·색인 | 스킬과 MCP 검색 도구를 통해 Claude가 필요한 대화 검색 | 매 요청에서 검색 실행을 보장하려면 별도 검색 연결 필요 |
| claude-obsidian | 기본 훅은 지식 작성·갱신을 하지 않음 | 스킬로 위키 조회; 선택형 시작 맥락 주입 기능 존재 | 완료된 작업을 선별해 위키에 저장하는 자동화 필요 |

근거: [내장 기억](https://code.claude.com/docs/en/memory), [episodic-memory 훅](https://github.com/obra/episodic-memory/blob/main/hooks/hooks.json), [검색 스킬](https://github.com/obra/episodic-memory/blob/main/skills/remembering-conversations/SKILL.md), [claude-obsidian 훅 문서](https://github.com/AgriciDaniel/claude-obsidian/blob/main/hooks/README.md).

## 훅·스킬·MCP의 역할

- **훅:** 언제 실행할지를 정합니다. 이벤트에 맞춰 등록된 처리를 실행합니다.
- **스킬:** 어떤 상황에서 무엇을 어떻게 할지 Claude에게 설명합니다. 실제 선택·준수는 모델의 판단에 영향을 받습니다.
- **MCP:** 검색·읽기·저장 같은 동작을 호출할 수 있게 합니다. 연결 자체가 모든 도구 호출을 자동으로 실행하지는 않습니다.
- **실행 스크립트:** 파일 수집·필터링·중복 확인·큐 처리처럼 정해진 절차를 담당합니다.

따라서 `CLAUDE.md`에 “필요하면 과거 대화를 검색해”라고 쓰는 구성과, 특정 이벤트마다 검색 프로그램이 실행되게 하는 구성은 다릅니다. 자동 호출을 구성하더라도 검색 관련성과 저장할 결론의 정확성은 별도로 판단해야 합니다. [공식 확장 기능 안내](https://code.claude.com/docs/en/features-overview)

## 권장 통합 흐름

| 시점 | 권장 처리 | 상태 |
|---|---|---|
| 세션 시작·재개 | 내장 기억 로드, 과거 대화 sync, 현재 프로젝트의 핵심 노트 확인 | 일부 제품 기본 기능 + 선택 설정 |
| 새로운 작업 접수 | 현재 프로젝트·질문을 기준으로 대화와 위키 검색 | 스킬 지침 또는 별도 검색 자동화 필요 |
| 구현·조사 중 | 새 근거·검증 결과와 출처를 작업 메모에 기록 | 별도 작업 스킬로 일관화 가능 |
| 작업 완료가 확인됨 | 결론·적용 조건·검증 결과를 추출하고 중복 노트 확인 | 별도 완료 처리 필요 |
| 위키 반영 | claude-obsidian의 정해진 저장·트랜잭션 절차로 노트 반영 | 기존 저장 기능을 호출하는 연결 필요 |
| 후속 작업 | 필요한 노트만 조회하고 현재 코드·자료와 대조 | 검색 지침 또는 별도 검색 자동화 필요 |

“훅이 실행되었다”와 “사용자 작업이 완료되었다”를 동일하게 취급하지 않는 것이 좋습니다. 완료 처리에는 해당 작업의 상태나 검증 결과를 조건으로 두는 설계를 권장합니다.

## 자동 저장할 내용의 기준

위키에 남길 후보:

- 사용자가 확정한 설계 결정과 대안·선택 이유
- 실제 확인한 오류 원인과 해결 방법, 재현·검증 결과
- 반복 사용할 명령·절차와 적용 환경
- 출처를 확인한 학습·조사 결과

대화 보관으로 충분한 내용:

- 아직 확인하지 않은 추측과 검토 중인 대안
- 같은 설명의 반복, 일시적인 진행 보고
- 전체 도구 출력·로그를 그대로 복제한 내용

이 구분은 권장 운영 기준입니다. 어떤 내용을 자동으로 확정 저장할지는 사용자의 작업 방식에 맞춰 설정할 수 있습니다.

## 검색 결과를 사용하는 기준

1. 현재 작업의 프로젝트·주제를 검색 범위에 반영합니다.
2. 과거 대화와 위키에서 필요한 근거만 가져옵니다.
3. 내용이 충돌하면 현재 코드·설정·원문 자료를 확인합니다.
4. 대화 속 추측과 검증된 위키 결론을 구분합니다.
5. 변경된 결정은 이전 이유를 남기면서 갱신합니다.

전체 기록을 매번 넣는 방식보다 현재 작업과 관련된 결과를 제한해 사용하는 설계를 권합니다. 이는 제품 간 기본 자동 연동을 설명하는 것이 아니라 별도로 구성할 검색 흐름입니다.

## 도구별 실제 설정 지점

### 내장 기억

Claude Code에서 `/memory`로 Auto memory 활성화와 저장 내용을 확인합니다. `CLAUDE.md`에는 지속적으로 적용할 규칙을 두고, 긴 참고 자료는 별도 문서나 스킬로 둡니다. [공식 문서](https://code.claude.com/docs/en/memory)

### episodic-memory

플러그인의 MCP와 훅이 활성화되어 있어야 합니다. 확인한 현재 훅은 `SessionStart`에서 `startup|resume|clear`에 대해 `sync --background`를 실행합니다. README의 종료 시 색인 설명과 다르므로 설치 버전의 실제 훅도 확인해야 합니다.

자동 검색은 `remembering-conversations` 스킬의 지침에 영향을 받습니다. 명시적인 회수 요청이 없어도 관련 상황에서 검색하도록 유도하지만, 모든 요청에서 검색을 보장하는 고정 실행은 아닙니다. [현재 훅](https://github.com/obra/episodic-memory/blob/main/hooks/hooks.json), [검색 스킬](https://github.com/obra/episodic-memory/blob/main/skills/remembering-conversations/SKILL.md)

선택형 요약을 끄는 환경변수는 `EPISODIC_MEMORY_SKIP_SUMMARIES=1`입니다. 요약을 꺼도 검색은 유지됩니다. `EPISODIC_MEMORY_DISABLE_AUTO_SYNC=1`은 자동 동기화 자체를 끄는 다른 설정입니다. [설정 문서](https://github.com/obra/episodic-memory#api-configuration)

### claude-obsidian

먼저 실제 사용할 보관함을 명시적으로 선택해야 합니다. 저장소는 `CLAUDE_OBSIDIAN_VAULT`, `.claude-obsidian.json` 등의 보관함 선택 방식을 설명합니다. 문서 폴더를 보관함으로 추정하지 않습니다. [공식 README](https://github.com/AgriciDaniel/claude-obsidian)

현재 훅의 동작:

- 기본 `SessionStart`는 조용히 동작합니다.
- `CLAUDE_OBSIDIAN_SESSION_CONTEXT=1`을 선택하면 제한된 `wiki/hot.md` 맥락을 제공할 수 있습니다.
- 프로젝트 설정이 외부 보관함을 지정한 경우에는 정확한 `CLAUDE_OBSIDIAN_SESSION_CONTEXT_VAULT` 경로 조건도 있습니다.
- 이 시작 훅은 `wiki/hot.md`를 생성·갱신하지 않습니다.
- `Stop`은 복구가 필요한 상태를 알리는 용도입니다.
- 기본 훅은 지식 작성, Git 커밋, 원격 호출을 수행하지 않습니다.

따라서 자동 위키 저장은 이 훅을 켜는 것만으로 완성되지 않습니다. `save`·`wiki-ingest`와 트랜잭션 코어를 정상적으로 호출하는 별도 연결이 필요합니다. [훅 문서](https://github.com/AgriciDaniel/claude-obsidian/blob/main/hooks/README.md)

## 실제 구현 전 정해야 할 값

| 항목 | 현재 상태 |
|---|---|
| 개발 프로젝트 위치 | 미지정 |
| 사용하는 언어와 LSP | 미지정 |
| Obsidian 보관함 경로 | `$HOME/claude/obsidian`으로 지정; 위키 초기화 미확인 |
| 자동 저장 범위 | 전역 CLAUDE.md에 선별 기준과 상시 저장 요청 명시 |
| 완료 판단 방법 | 검증된 작업 완료 여부를 모델이 판단하는 지침; 강제 완료 훅은 없음 |
| 과거 대화 검색 범위 | 현재 프로젝트·주제 우선, 필요한 경우 확장하도록 지침 지정 |
| 위키 저장 호출·재시도·중복 처리 | 설치된 워크플로 사용·중복 확인·성공 검증을 지침에 명시; 실제 연동 미검증 |

현재 모델이 따를 전역 지침까지 적용했습니다. 플러그인 연결과 보관함 초기화 상태를 확인하고 실제 저장·검색을 검증해야 자동 운영이 완성됩니다.
