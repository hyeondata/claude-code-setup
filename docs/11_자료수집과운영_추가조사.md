## 읽기 전에 구분할 것

- **MCP:** 에이전트가 호출할 도구를 연결하는 인터페이스입니다.
- **플러그인:** MCP 설정·skill·명령 등을 묶어 배포할 수 있습니다. 무엇이 포함되는지는 제품마다 다릅니다.
- **CLI:** 셸에서 실행하는 프로그램입니다. Claude Code가 CLI를 사용할 수 있으면 MCP를 추가하지 않아도 됩니다.
- **Skill:** 도구를 언제 어떻게 사용할지 안내하는 작업 지침입니다. 실행 프로그램이나 API 계정을 대신하지 않습니다.
- **로컬 서버:** MCP 프로세스의 위치를 뜻합니다. 그 서버가 호출하는 클라우드 API까지 로컬인 것은 아닙니다.
- **로컬 변환:** 파일을 로컬에서 변환해도, 결과를 Claude에 전달하는 단계의 데이터 흐름은 별도입니다.
- **자동화:** MCP 설치만으로 폴더 감시·정기 실행·새 문서 자동 저장이 생기지 않습니다.

## 1. Tavily: Exa의 대안이 될 검색·추출 묶음

### 용도와 선택 기준

Tavily는 웹 검색, URL 본문 추출, 사이트 탐색, 여러 출처를 사용하는 조사를 제공합니다.
공식 MCP에는 Search·Extract·Crawl·Map·Research 도구가 포함됩니다.
검색 결과를 찾은 뒤 본문을 추출하는 흐름을 같은 서비스 안에서 구성하고 싶을 때 검토합니다.
Exa가 현재 작업에 충분하면 둘을 동시에 추가할 이유는 약합니다.

### 인증·비용·운영

- **형태:** 업체가 호스팅하는 MCP와 로컬 실행 구성을 안내합니다.
- **인증:** Claude Code의 원격 연결은 OAuth를 지원하며 API 키 방식도 있습니다.
- **키 없는 사용:** Search·Extract에 제한된 keyless 접근이 있습니다. 전체 도구의 무제한 무료 사용은 아닙니다.
- **비용:** 계정에 무료 월별 크레딧이 있으며, 월 요금제와 사용량 결제가 있습니다.
- **과금 차이:** 검색 깊이, 추출 페이지, 사이트 탐색, Research에 따라 소모 방식이 다릅니다.
- **처리 위치:** 로컬 MCP나 `mcp-remote`를 실행해도 Tavily API의 처리 위치는 클라우드입니다.

### 중복과 한계

Exa와는 검색·본문 읽기, Firecrawl과는 추출·사이트 수집에서 겹칩니다.
Research의 생성 보고서는 수집한 원문과 구분해 보관하는 편이 좋습니다.
새 보고서가 나왔다고 Obsidian에 자동 입력되는 기능은 이번 연결에 포함되지 않습니다.
먼저 같은 질문·같은 URL로 기존 도구와 비교할 필요가 있는지 판단하세요.

1차 자료: [공식 MCP·인증·도구](https://docs.tavily.com/documentation/mcp), [크레딧·과금 구조](https://docs.tavily.com/documentation/api-credits).

## 2. Brave Search MCP: 검색 결과의 공급자를 바꾸는 선택

### 용도와 선택 기준

Brave가 관리하는 공식 MCP 서버로 웹·뉴스·이미지·영상·장소 검색 등을 제공합니다.
일반 웹 검색을 보강하거나, 기존 검색 공급자와 다른 결과가 필요한 경우에 맞습니다.
검색어를 넣어 출처 후보를 찾는 단계에 우선 배치합니다.
독립 검색 공급자라는 점과 모든 질의에서 더 좋은 결과를 낸다는 주장은 구분해야 합니다.

### 인증·비용·운영

- **형태:** 로컬 MCP 서버이며 STDIO와 HTTP 전송을 지원합니다.
- **인증:** `BRAVE_API_KEY` 또는 키 파일 설정이 필요합니다.
- **비용:** MCP 코드의 라이선스와 Brave Search API 비용은 별개입니다.
- **API 요금:** 현재 공식 페이지는 선불 크레딧과 무료 제공 크레딧을 안내합니다.
- **주의:** 오래된 글의 무료 검색 횟수·정액 요금을 그대로 가져오지 말고 현재 대시보드를 확인합니다.
- **처리 위치:** 서버 실행은 로컬이어도 검색 요청은 Brave API로 전송됩니다.

### 중복과 한계

Exa·Tavily와 검색 공급자 역할이 겹치므로 처음에는 하나를 고르는 편이 낫습니다.
검색 결과·요약과 원문 전체를 동일하게 취급하지 않습니다.
문서 파일 OCR이나 로컬 PDF 변환에서는 Docling·MarkItDown의 역할을 대체하지 않습니다.
개인 Claude Code에서는 서버를 네트워크에 공개할 필요 없이 로컬 STDIO 구성을 검토할 수 있습니다.
기본 HTTP 엔드포인트를 외부 공개 서비스로 취급하지 않습니다.

1차 자료: [Brave 공식 MCP 저장소](https://github.com/brave/brave-search-mcp-server), [현재 Search API·과금 안내](https://brave.com/search/api/).

## 3. Jina AI Remote MCP / Reader: URL을 읽기 위한 얇은 연결

### 용도와 선택 기준

Jina의 공식 원격 MCP는 Reader·검색·재정렬 등의 API를 도구로 제공합니다.
`read_url`은 웹페이지 또는 PDF URL을 Markdown으로 읽는 데 맞습니다.
URL을 이미 알고 있고 그 내용을 가져오는 간단한 경로가 필요할 때 검토합니다.
Reader의 HTTP API를 셸에서 호출할 수는 있지만, 이를 별도의 공식 전용 CLI로 단정하지 않습니다.

### 인증·비용·운영

- **형태:** 공식 원격 MCP와 HTTP API입니다.
- **인증:** `read_url`은 키 없이 제한적으로 사용 가능하지만, 검색·일부 PDF 추출 도구는 키가 필요합니다.
- **비용:** API 토큰 사용량과 충전 잔액에 기반한 요금 구조이며 무료 사용 범위·속도 제한이 있습니다.
- **차이:** 일반 읽기, 검색, OCR 등은 동일한 비용·출력 방식을 가정하면 안 됩니다.
- **처리 위치:** 호스팅 Reader가 대상 URL을 가져와 처리합니다. 로컬 프록시를 둬도 같다는 점에 주의합니다.
- **로컬 파일:** 호스팅 서버가 사용자의 임의 로컬 경로를 직접 읽는 구성은 아닙니다.

### 중복과 한계

일반 HTML 본문 읽기는 Defuddle, 원격 수집·파싱은 Firecrawl과 겹칩니다.
로컬 PDF를 로컬에서 처리하려는 목적에는 Docling·MarkItDown이 더 직접적인 선택입니다.
질문을 붙여 관련 부분만 반환하는 모드는 원문 전체 보관과 목적이 다릅니다.
부분 추출·잘림·표와 코드 손실 여부를 확인하고 원본 URL을 함께 남깁니다.
서버 코드의 공개 라이선스가 모든 Reader 모델의 상업용 자체 호스팅 권리까지 보장하지는 않습니다.

1차 자료: [공식 원격 MCP·도구별 인증](https://github.com/jina-ai/MCP), [Reader API·요금·처리 방식·모델 조건](https://jina.ai/reader/).

## 4. Microsoft MarkItDown: 오피스 파일의 Markdown 전처리

### 용도와 선택 기준

Microsoft의 Python 도구로 PDF·Word·PowerPoint·Excel 등 여러 형식을 Markdown으로 바꿉니다.
DOCX 회의 자료, PPTX 발표 자료, XLSX 표를 텍스트 작업의 입력으로 만들 때 검토합니다.
같은 일을 CLI로 충분히 처리할 수 있다면 MCP 등록을 먼저 할 필요는 없습니다.
공식 `markitdown-mcp`는 변환 기능을 MCP로 호출하는 별도 패키지입니다.

### 인증·비용·운영

- **형태:** CLI·Python 라이브러리·공식 MCP입니다.
- **인증:** 기본 로컬 변환에 외부 API 키가 필수인 것은 아닙니다.
- **비용:** 기본 변환은 로컬 연산 비용이며, 선택한 Azure·LLM 기능은 별도 API 비용이 생길 수 있습니다.
- **처리 위치:** 기본 변환과 Azure Document Intelligence·Content Understanding 경로를 구분합니다.
- **OCR:** LLM Vision을 사용하는 별도 OCR 플러그인이 있습니다. 이를 기본 로컬 OCR로 소개하면 안 됩니다.
- **접근 범위:** MCP는 파일·웹 URI를 받아 변환하므로 서버 프로세스의 파일 접근 권한이 중요합니다.

### 중복과 한계

Docling과 문서 변환이 겹치지만, 먼저 입력 문서 유형으로 판단하는 편이 좋습니다.
오피스 파일을 간단히 텍스트화하려면 MarkItDown, 복잡한 PDF 레이아웃·로컬 OCR은 Docling을 먼저 검토합니다.
이 구분은 기능과 운영 방식에 따른 추천이며 우열을 측정한 결과가 아닙니다.
변환 결과가 사람이 보는 원본의 배치·도형·표를 완전히 보존한다고 가정하지 않습니다.
Obsidian에는 결과 Markdown을 별도 전달해야 하며 파일을 변환했다고 자동으로 지식 노트가 생기지는 않습니다.

1차 자료: [Microsoft 공식 저장소](https://github.com/microsoft/markitdown), [공식 MCP 패키지·URI·로컬 실행 범위](https://github.com/microsoft/markitdown/tree/main/packages/markitdown-mcp).

## 5. Zotero MCP: 논문 파일보다 서재 전체가 중요한 경우

### 공식성부터 구분

이번에 검토한 것은 커뮤니티 프로젝트 **`54yyyu/zotero-mcp`**입니다.
Zotero 자체가 제공하는 공식 MCP라고 표시하면 안 됩니다.
프로젝트 관리자의 저장소를 기능·운영 조건의 1차 자료로 사용했습니다.
서지정보·첨부 논문·주석을 함께 검색해야 할 때 단순 PDF 변환기와 차이가 생깁니다.

### 형태·인증·비용

- **형태:** MCP 외에 `zotero-cli`와 agent skill, Zotero 내부 대화 플러그인을 제공합니다.
- **Claude Code:** 셸을 쓰는 에이전트에는 CLI+skill 경로도 안내하므로 MCP와 비교해 선택할 수 있습니다.
- **로컬 모드:** 로컬 라이브러리 읽기와 Zotero 로컬 기능을 사용합니다.
- **웹 모드:** Zotero API 키·라이브러리 식별자 등 별도 설정이 필요합니다.
- **쓰기:** 읽기와 권한을 구분해야 하며 로컬 쓰기는 Zotero 버전·인가 조건을 확인해야 합니다.
- **비용:** MCP·CLI는 공개 소스이며, 선택한 외부 임베딩·LLM 서비스에는 별도 비용이 생길 수 있습니다.

### 운영과 대체 관계

의미 검색은 선택 기능이며 로컬 또는 외부 임베딩 경로에 따라 데이터 흐름이 달라집니다.
프로젝트의 MCP·CLI와 Zotero 내부 플러그인은 라이선스도 동일하지 않습니다.
Docling·MarkItDown이 파일을 변환한다면 이 도구는 서재의 항목·인용·첨부물·주석을 찾는 쪽에 가치가 있습니다.
논문이 몇 개 없고 서지 관리를 하지 않는다면 새 Zotero 환경부터 만들 필요는 없습니다.
Zotero 주석을 Obsidian에 자동 반영하는 기본 통합이라고 해석하지 않습니다.

1차 자료: [관리자 저장소·세 가지 인터페이스·라이선스](https://github.com/54yyyu/zotero-mcp), [Zotero 공식 개발 API 안내](https://www.zotero.org/support/dev/client_coding/javascript_api).

## 6. Atlassian Rovo MCP: Jira·Confluence의 업무 맥락

### 용도와 선택 기준

Atlassian의 공식 원격 MCP입니다.
Jira 작업과 Confluence 문서 등 팀 업무 데이터를 검색·요약하고 허용된 작업을 실행합니다.
개발 요구사항의 근거, 관련 이슈, 기존 결정 문서를 코드 작업과 함께 볼 때 유용합니다.
이미 Jira·Confluence를 쓰는 팀에서 도입 이유가 명확합니다.

### 인증·비용·운영

- **형태:** Atlassian이 운영하는 원격 MCP입니다.
- **인증:** 대화형 사용에는 OAuth 2.1이 권장됩니다.
- **비대화형:** 관리자 허용 시 API 토큰·서비스 계정 키 경로가 제공됩니다.
- **권한:** 인증한 사용자의 기존 앱 권한과 범위를 따릅니다. 인증 방식에 따라 제공 도구도 다릅니다.
- **비용:** 일부 도구는 Rovo 크레딧을 사용하며 사용량은 가져오는 맥락과 작업에 따라 달라집니다.
- **청구:** 유료 Atlassian 플랜의 조직 크레딧·추가 사용 설정을 확인해야 합니다.
- **처리 위치:** 로컬 지식 저장소가 아니라 Atlassian 클라우드에 있는 업무 데이터에 접근합니다.

### 중복과 한계

앞서 소개한 Linear MCP와 이슈 맥락 접근 목적이 겹치므로 실제 업무 원장을 기준으로 고릅니다.
공개 웹 수집기·파일 OCR 도구를 대체하는 후보는 아닙니다.
공식 문서의 현재 연결 주소는 `/v2/mcp`이므로 오래된 `/v1/sse` 예제를 그대로 복사하지 않습니다.
MCP에 연결했다고 이슈 변화가 Claude Code나 Obsidian으로 자동 배달되지는 않습니다.
정기 요약·상태 변화 감시는 별도 트리거와 실행 주체를 설계하는 작업입니다.

1차 자료: [공식 시작 안내·현재 주소](https://developer.atlassian.com/cloud/rovo-mcp/guides/getting-started/), [인증·도구별 조건](https://developer.atlassian.com/cloud/rovo-mcp/guides/authentication-and-authorization/), [Rovo 크레딧·청구](https://www.atlassian.com/licensing/rovo).

## 7. Notion MCP: 이미 쌓인 팀 문서를 코드 작업에 사용

### 용도와 선택 기준

Notion이 운영하는 공식 MCP로 권한이 있는 페이지·데이터베이스를 검색하고 읽고 갱신합니다.
요구사항·회의록·결정 기록이 Notion에 있다면 이를 코드 작업의 근거로 사용할 수 있습니다.
Notion의 공식 연결 문서는 MCP·skill·명령을 묶은 Claude Code 플러그인도 안내합니다.
플러그인을 선택했다면 동일한 MCP를 별도로 중복 등록할 필요가 있는지 먼저 확인합니다.

### 인증·비용·운영

- **형태:** 권장 경로는 공식 호스팅 MCP이며 Claude Code에서 OAuth 인증을 안내합니다.
- **권한:** 선택한 워크스페이스에서 사용자가 접근할 수 있는 콘텐츠를 기준으로 작동합니다.
- **비용:** 도구별 제공 범위는 워크스페이스 플랜·Notion AI 접근에 따라 달라집니다.
- **제한:** 연결된 외부 소스 검색 등은 Business·Enterprise와 Notion AI 조건을 확인해야 합니다.
- **단가:** 검토한 MCP 문서에서 모든 호출에 적용되는 별도 단일 요금은 확인하지 못했습니다.
- **로컬 대안:** 기존 오픈소스 `notion-mcp-server`는 공식 문서상 적극 유지보수가 중단됐습니다.
- **처리 위치:** 로컬 서버를 사용하더라도 Notion 콘텐츠는 Notion 서비스와 통신합니다.

### 중복과 한계

외부 소스 연결 검색은 해당 소스가 실제 연결돼 있고 사용자에게 접근권이 있어야 합니다.
Notion에 있는 문서를 Obsidian으로 전부 복제하는 것보다 원본 링크와 필요한 결정만 남기는 방법을 검토합니다.
Notion의 기억 관련 도구가 존재해도 Claude Code의 모든 대화를 기본 자동 저장한다는 뜻은 아닙니다.
도구 목록에 보이는 것과 현재 계정 플랜에서 실행할 수 있다는 것도 구분해야 합니다.
설치·OAuth 완료만으로 claude-obsidian와 양방향 동기화되지 않습니다.

1차 자료: [공식 연결·Claude Code 플러그인](https://developers.notion.com/guides/mcp/get-started-with-mcp), [도구·플랜·기억 검색](https://developers.notion.com/guides/mcp/mcp-supported-tools), [로컬 서버 유지보수 상태](https://developers.notion.com/guides/mcp/hosting-open-source-mcp).

## 8. Bytebase DBHub: SQL 데이터 조회가 필요한 개발·운영 작업

### 용도와 선택 기준

Bytebase가 관리하는 MCP로 PostgreSQL·MySQL·SQLite 등 여러 DB에 연결합니다.
스키마 이해, 조회 쿼리 확인, 데이터에 근거한 오류 분석에 맞습니다.
기본 도구에는 SQL 실행과 DB 객체 검색이 있으며, 필요한 도구만 노출하는 구성을 지원합니다.
Supabase 전용 프로젝트 관리가 아니라 일반 SQL DB 접근이 필요한 경우의 대안입니다.

### 인증·비용·운영

- **형태:** 로컬·직접 운영 MCP이며 공식 Claude Code 플러그인 배포 경로도 있습니다.
- **인증:** DB 연결 문자열과 해당 DB의 인증 정보가 필요합니다.
- **비용:** 공개 소스 서버 자체와 DB 운영·호스팅·Claude 사용 비용을 구분합니다.
- **처리 위치:** DBHub 실행 위치에서 지정한 DB에 접속합니다. DB가 로컬일 수도 원격일 수도 있습니다.
- **외부 전달:** 조회 결과를 Claude에 넘기면 DB 안에 있던 정보가 모델 입력에 포함될 수 있습니다.
- **자동화:** SQL 조회 도구이며 스스로 정기 모니터링·알림을 시작하는 구성은 아닙니다.

### 읽기 전용으로 검토할 때의 실제 조건

`readonly = true`는 현재 문서에서 도구별 설정이며, DB 사용자 권한과 함께 적용해야 합니다.
공식 보안 권고에는 0.22.6 미만 버전의 읽기 전용 강제 누락 문제가 기록돼 있습니다.
0.22.6은 해당 수정 버전이지 이 문서에서 보장하는 최신 버전 번호가 아닙니다.
새 도입 시 현재 패치 상태를 확인하고, 관리자 계정 대신 필요한 테이블·뷰만 읽는 DB 계정을 사용합니다.
반환 행 수·쿼리 시간 제한을 두고, 처음에는 스키마 조회나 미리 정의한 조회만 노출할 수도 있습니다.
read-only 표시 하나만으로 모든 특권 함수·외부 부작용까지 차단된다고 해석하면 안 됩니다.

1차 자료: [DBHub 공식 저장소·지원 DB·배포 형태](https://github.com/bytebase/dbhub), [SQL·읽기 전용·도구 제한](https://github.com/bytebase/dbhub/blob/main/docs/tools/execute-sql.mdx), [공식 보안 권고·수정 버전](https://github.com/bytebase/dbhub/security/advisories/GHSA-mwwr-p57h-56pf).

## 기존 추천과 어떻게 조합할지

| 부족한 기능 | 이번 후보 | 앞선 도구와의 관계 | 최소 구성 판단 |
|---|---|---|---|
| 웹 검색 결과가 만족스럽지 않음 | Tavily 또는 Brave | Exa 대안 | 같은 역할은 우선 하나 |
| 이미 아는 URL 본문 읽기 | Jina Reader | Firecrawl·Defuddle와 겹침 | 현재 추출 실패 사례가 있을 때 검토 |
| Office 첨부파일 텍스트화 | MarkItDown | Docling과 일부 중복 | 입력 파일 유형으로 선택 |
| 논문·인용·주석을 함께 검색 | Zotero 커뮤니티 도구 | 파일 변환기와 다른 역할 | Zotero 서재가 있을 때 가치가 큼 |

## claude-obsidian에 넣는 단계는 별도

위 후보 어느 것도 설치만 하면 claude-obsidian에 기본 자동 연동되는 것으로 확인하지 않았습니다.
웹 검색·파일 변환·업무 조회 결과를 만든 뒤, 선택한 내용을 Markdown으로 전달하는 단계를 둡니다.

1. 검색 결과나 업무 링크에서 보관할 원본을 고릅니다.
2. 필요하면 본문·첨부파일을 추출하고 원본과 대조합니다.
3. 원본 URL·문서 식별자·저자·발행일·수집일을 확보한 범위에서 남깁니다.
4. 원문 추출물과 AI 요약·판단을 구분합니다.
5. 사용자가 정한 inbox·노트 위치에 전달하는 별도 작업을 실행합니다.
6. 이후 분류·링크·중복 처리를 지식 관리 흐름에서 수행합니다.

이 과정은 제안하는 연결 방식이며 이번 조사에서 실행하거나 설정한 자동화가 아닙니다.
폴더 감시, Zotero 변경 감지, Notion 이벤트, 일정 실행은 별도 설계·인증·오류 처리 범위를 가집니다.
자료 수집 성공과 원본 갱신 추적, 지식 노트 유지보수는 서로 다른 문제입니다.

## 우선 추천 3개

1. **MarkItDown:** DOCX·PPTX·XLSX 등 입력 자료가 많다면 먼저 검토합니다. CLI로 충분한지부터 판단합니다.
2. **Zotero 커뮤니티 도구:** 이미 Zotero에 논문과 주석이 있다면 서재 활용 효과가 큽니다. 공식성·모드·읽기 권한부터 구분합니다.
3. **Tavily:** 기존 Exa만으로 부족한 검색·추출 사례가 있을 때 비교 후보로 둡니다. 처음부터 둘 다 기본 설치할 필요는 없습니다.

Notion·Jira·Confluence가 현재 업무의 중심이면 3순위를 해당 공식 MCP로 바꾸는 편이 더 실용적입니다.
DBHub는 실제 DB 조회 필요와 읽기 권한을 준비할 수 있을 때 추가하는 전문 후보입니다.
입력 자료나 사용 중인 서비스가 없다면 이 목록에서 아무것도 추가하지 않아도 됩니다.

## 미검증 사항과 이번 범위 밖

- 사용자 환경에서의 설치 성공, 로그인, 실제 도구 노출, 개별 계정 플랜은 검증하지 않았습니다.
- 한국어 검색 품질, 한글 OCR, 복잡한 표·수식·PPT 배치 보존을 비교 실험하지 않았습니다.
- Jina의 별도 공식 전용 CLI 존재는 확인하지 않아 원격 MCP·HTTP API로만 분류했습니다.
- Zotero MCP라는 이름의 여러 프로젝트를 전부 검토한 것이 아닙니다. 검토한 저장소를 명시했습니다.
- Notion의 계정별 호출 한도와 최종 청구액, Rovo 조직별 크레딧 설정은 확인하지 않았습니다.
- DBHub의 수정 버전 근거를 확인했지만 사용자의 설치 버전·실제 DB 권한은 조사하지 않았습니다.
- Sentry Seer, OpenTelemetry, ccusage는 이번 8개 심층 조사에서 제외했습니다. 앞선 Sentry 소개를 이 문서로 확장했다고 보지 않습니다.
- 자동 저장 트리거·양방향 동기화·claude-obsidian 네이티브 어댑터는 구현하거나 검증하지 않았습니다.
