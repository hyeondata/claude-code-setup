# 추가 조사 후 추천 우선순위와 조합

> 설치 후 갱신: 두 기억 플러그인·자동 훅·Obsidian 보관함·공식 Dart/Flutter 도구를 구성했고 실제 저장·검색을 검증했습니다. Context7 로그인은 나중에 진행합니다. 아래는 설치 전 추천 근거이며, 현재 상태는 [13 설치 결과](13-installed-memory.md)를 우선합니다.

기준일: **2026-11-01**. 이 문서는 [내장 기능](08-built-in-features.md), [기억·검색 도구](09-memory-research.md), [개발 도구](10-development-research.md), [자료 수집·운영 도구](11-integration-research.md)의 비교 결과에 따른 추천이다. 각 기능·비용·조건의 원문 링크는 해당 상세 문서에 있다.

## 1. 지금 구성은 유지하고, 부족한 역할에만 추가

현재 목적에 맞는 기본 구성:

| 역할 | 기본 선택 | 추가 검토 계기 |
|---|---|---|
| 코드 탐색·진단 | 언어 LSP, 필요한 경우 Serena | 여러 파일에서 같은 문법 구조를 찾을 때 ast-grep |
| 라이브러리 문서 | Context7 | 넓은 웹 조사라면 검색 서비스 하나 |
| 코드 검토 | 내장 `/code-review` | 실제 앱 검증, 규칙 기반 보안 검사 등이 부족할 때 보완 |
| 선호·행동 규칙 | Auto memory + 영어 `CLAUDE.md` | 프로젝트·파일별 규칙이 늘면 `.claude/rules/` |
| 과거 대화 | episodic-memory | 더 강한 자동 문맥 주입·여러 도구 공유가 필요할 때 대체 제품 비교 |
| 사람이 읽는 지식 | claude-obsidian | 표현이 다른 노트를 놓칠 때 QMD |

**지금 가장 큰 미완료 항목은 새 기억 제품의 추가가 아니라, 선택한 도구의 실제 연결·저장·검색 검증이다.** 전역 지침에는 자동 기록·검색 정책과 `$HOME/claude/obsidian` 경로를 이미 넣었다. 지침 파일 적용이 도구 설치나 위키 초기화를 대신하지는 않는다. [현재 적용 상태](07-claude-policy.md)

## 2. 먼저 추천할 추가 기능

| 추천 | 언제 유용한가 | 현재 구성과의 관계 | 도입 판단 |
|---|---|---|---|
| 내장 진단 명령 | 규칙·MCP·기억이 안 보이거나 작동 여부가 불명확 | 구성 검증 | 지금 먼저 |
| 경로별 rules | API·UI·테스트 규칙이 서로 다름 | 전역 지침 보완 | 프로젝트가 커질 때 |
| 서브에이전트 기억 | 리뷰·디버깅 역할을 반복 사용 | 역할별 기억 추가 | 반복 전문 작업이 있을 때 |
| ast-grep | API 마이그레이션·문법 패턴 변경 | LSP·텍스트 검색 보완 | 해당 개발 작업이 많으면 우선 |
| Repomix | 코드 일부를 묶어 검토·인수인계 | 일회성 코드 자료 생성 | 필요한 작업에서 사용 |
| QMD | 노트 표현과 질문 표현이 달라 검색 누락 | 기존 위키에 검색만 추가 | 노트·실패 질의를 모은 뒤 평가 |
| Playwright CLI + skills | 브라우저를 명령 중심으로 제어 | Playwright MCP의 대안 | 둘 중 맞는 방식 하나부터 |
| Flutter 공식 도구 | 앱 오류·위젯 트리·hot reload 확인 | 언어 탐색에 실행 상태 추가 | Flutter/Dart 개발이면 우선 |
| 내장 `/goal` | 완료 조건까지 여러 턴 작업 | 반복 플러그인과 비교 | 명확한 검증 조건이 있을 때 |
| MarkItDown | Office·PDF 등 여러 형식을 텍스트로 변환 | 자료 수집 전처리 추가 | 해당 문서가 많을 때 |

일반 앱 개발이라면 **ast-grep·Repomix**, 지식관리라면 **QMD**, 웹 개발이라면 **Playwright 방식 선택**, Flutter라면 **공식 Dart/Flutter 도구**가 추가 검토의 중심이다. 모두 상시 실행해야 하는 필수 도구라는 뜻은 아니다.

## 3. 추가와 대체를 구분

| 후보 묶음 | 선택 방식 | 이유 |
|---|---|---|
| episodic-memory / claude-mem / Supermemory / Mem0 / Hindsight | 주 대화 기억 방식을 하나 정하고 비교 | 수집·저장·주입이 중첩될 수 있음 |
| claude-obsidian + QMD | 작성과 검색을 분리해 함께 평가 가능 | 같은 원문에 대한 검색 보강 |
| claude-obsidian + MCPVault | 다른 AI가 읽어야 할 때 읽기 전용 연결 검토 | 위키 작성 절차를 우회하지 않고 접근 확대 |
| MCPVault / Obsidian Local REST API | 파일 접근인지 실행 중 앱 제어인지에 따라 선택 | Obsidian 실행 필요 여부와 도구 범위가 다름 |
| Playwright MCP / Playwright CLI / agent-browser | 주 브라우저 경로 하나부터 | 조작 기능이 크게 겹침 |
| LSP·Serena / jCodeMunch | 기존 탐색이 부족한 경우 대체 평가 | 새 색인의 운영·라이선스 비용 고려 |
| Exa / Tavily / Brave | 검색 목적과 API·요금 조건에 맞춰 하나부터 | 웹 검색 서비스 중복 |
| Defuddle / Jina Reader / Firecrawl | 단일 문서 정리·호스팅 추출·크롤링 범위로 선택 | 같은 URL을 여러 도구가 중복 처리할 수 있음 |
| MarkItDown / Docling | 단순 형식 변환·문서 구조/OCR 요구에 따라 선택 | 출력 품질은 문서 샘플로 확인 |
| Superpowers / feature-dev / GSD / ECC | 주 개발 절차 하나부터 | 계획·리뷰·진행 규칙의 중첩을 줄임 |

이 표는 상호 호환성 시험 결과가 아니라 기능과 운영 부담에 따른 선택 가이드다.

## 4. 현재 단계에서 후순위인 항목

- **Supermemory·Mem0·Hindsight:** 좋은 기능이 있지만 현재 선택한 대화 기억을 유지하면서 모두 추가할 근거는 약하다. 자동 회상 시점·클라우드 공유가 핵심 요구가 되면 대체 평가한다.
- **Pieces:** 코딩 대화 밖의 앱·업무 맥락을 기억해야 할 때 검토한다.
- **Letta:** 장기 상태를 가진 별도 에이전트 환경에 일을 맡기려는 경우에 검토한다.
- **Sourcegraph MCP:** 이미 Sourcegraph Enterprise를 쓰는 조직에 의미가 크다.
- **jCodeMunch:** 현재 LSP·Serena로 해결되지 않는 탐색 문제와 상업 사용 조건을 먼저 확인한다.
- **Docker MCP Toolkit:** 여러 MCP의 의존성·프로필 관리가 실제 부담이 될 때 도입한다.
- **RTK:** 긴 명령 출력이 병목일 때 필터부터 비교하고, 처음부터 API 프록시·라우팅까지 추가하지 않는다.
- **Agent teams·Channels·SDK:** 구체적인 병렬 협업·이벤트 처리·별도 자동화 프로그램이 필요할 때 검토한다.

## 5. 한국어 지식 검색은 이렇게 평가

지침은 영어지만 답변과 개인 지식 노트의 기본 언어는 한국어로 설정했다. 검색 도구는 영어 자료에서의 홍보 수치만으로 고르지 않는다.

아래는 실행하지 않은 평가 방법 제안이다.

1. 실제로 다시 찾을 만한 노트 10~20개를 준비한다. 각 노트의 정답 경로와 핵심 문장을 기록한다.
2. 같은 내용을 한국어·영어·용어 혼합으로 질문한다. 예: `로그인 만료 후 재인증`, `token refresh failure`, `세션 갱신 실패`.
3. 정확한 키워드가 없는 질문, 비슷하지만 다른 문제, 오래되어 갱신된 결정도 포함한다.
4. 기존 검색과 새 도구에 같은 질문을 주고, 올바른 노트와 원문 근거를 찾는지 확인한다.
5. 노트를 고친 뒤 재검색하여 갱신이 반영됐는지 확인한다.
6. 색인 시간, 메모리·디스크 사용, 질의 지연, 실제 모델 사용량을 함께 본다.

QMD README는 기본 임베딩의 CJK 한계와 모델 교체 옵션을 설명한다. 한국어 품질은 실제 노트로 평가해야 하며, 모델 교체 시 기존 벡터를 그대로 재사용하지 않는다. [QMD 모델 안내](https://github.com/tobi/qmd#custom-embedding-model)

## 6. 사용 상황별 권장 조합

### 개인 개발과 가벼운 지식관리

- 현재 기본 구성 유지.
- `.claude/rules/`로 프로젝트 규칙만 분리.
- ast-grep·Repomix는 해당 작업에서 사용.
- 노트가 적으면 추가 검색 서버는 보류.

### 문서·학습 자료가 많이 쌓이는 개발자

- 현재 기본 구성 + QMD 검색 평가.
- 웹 검색 서비스 하나 + 추출기 하나를 목적에 맞게 선택.
- Office 자료가 많으면 MarkItDown, 구조 분석·OCR 요구가 크면 Docling과 샘플 비교.
- 논문 서지·라이브러리를 이미 Zotero에 관리한다면 Zotero 연동 후보 검토.

### 웹 앱 개발

- 현재 기본 구성 + frontend-design.
- Playwright CLI 또는 MCP 중 하나, 성능·네트워크 심층 조사는 Chrome DevTools와 역할 분담.
- Figma를 원본으로 쓰는 프로젝트에서만 Figma 연결.
- 보안 규칙 검사가 필요하면 Semgrep Guardian의 비용·원격 처리 조건 검토.

### Flutter/Dart 개발

- Flutter 팀 공식 플러그인 또는 Dart SDK MCP 경로를 선택.
- 지원 SDK와 실행 중 앱 연결을 확인.
- Claude Code가 플러그인 rules를 자동 로드하지 않는 부분은 프로젝트 지침에 필요한 규칙을 명시.
- 같은 이름의 커뮤니티 패키지와 공식 `flutter/agent-plugins`를 구분. [Flutter 공식 안내](https://docs.flutter.dev/ai/get-started)

### 팀·여러 저장소·업무 서비스 연결

- 이미 사용하는 Jira/Confluence면 Rovo, Notion이면 공식 Notion MCP·플러그인을 검토.
- 조직 코드 검색이 필요하고 해당 서비스를 사용 중이면 Sourcegraph MCP.
- DB 조사에는 DBHub 같은 도구와 필요한 데이터 접근 범위를 별도로 설정.
- 팀 공용 기억이 필요하면 Basic Memory·Hindsight·Mem0 등의 저장·공유 모델을 먼저 비교.

## 7. 설정 파일에 무엇을 넣을 것인가

| 위치 | 넣을 내용 | 이번 작업 상태 |
|---|---|---|
| 전역 `CLAUDE.md` | 공통 언어, 기억 역할, 검색·저장 조건 | 앞선 요청에서 적용 완료, 이번 조사로 추가 변경하지 않음 |
| 프로젝트 rules | 특정 경로·언어·테스트 규칙 | 프로젝트가 정해지면 선택 |
| Skill | 반복되는 긴 절차와 검증 순서 | 실제 반복 필요가 생기면 작성 |
| settings/MCP/plugin 등록 | 실행 파일·서버·인증·훅 | 이번 조사에서 추가 등록하지 않음 |
| Obsidian | 검증된 지식과 출처 | 이번 조사는 추천 문서 폴더에 저장; 위키에 자동 반영하지 않음 |

조사한 도구 이름을 모두 전역 지침에 넣으면 사용 불가능한 도구와 중복 절차가 늘어난다. 실제 선택·연결한 기능의 역할만 지침에 반영하는 것이 좋다.
